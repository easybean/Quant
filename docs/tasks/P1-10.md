## 更新合同

- 使用独立 `yahoo-daily-v1` namespace；无数据标的从 2016-01-01 补历史，已有标的按最近日期回查七天，不每天下载十年全量。
- 下载器返回的原始 DataFrame 先按不可变 run ID 保存并登记 SHA-256，再标准化并发布可变合并视图；同日期修订更新视图但原批次保留，旧研究快照不修改。缺失公司行为字段保持未知，不将其当作零事件。
- 截止日保守排除尚未结束的纽约日，不臆造交易日或历史 `available_time`。
- 进程锁防并发；失败保留旧文件，连续三次失败停止。摘要记录窗口、获取时间、成功/失败与延期，不记录凭证或异常全文。
- 冷启动每次最多补 100 个无数据标的；已有 Yahoo 序列每日全部更新，不能把轮转子集宣称为全市场日更。

## 定时与运维

用户级 `quant-yahoo-daily.timer` 每日北京时间 11:30 后随机延迟最多五分钟执行。失败不热重启，`Persistent=true` 补跑错过的执行；开机持续运行依赖用户 manager/linger。

```bash
systemctl --user status quant-yahoo-daily.timer
systemctl --user list-timers quant-yahoo-daily.timer
journalctl --user -u quant-yahoo-daily.service -n 30 --no-pager
```

摘要：`data/manifests/yahoo-daily-v1/latest.json`。定时器正常不等于下载成功，受阻必须保留 failed/partial。新数据仍需质量审查和浏览索引刷新，不能自动成为合格回测输入。

当前行情浏览索引是固定审计快照，不会因新下载自动刷新；本阶段不得宣称网页已显示新行情。失败可在 journal 与状态 JSON 中查询，尚未接入短信/邮件等外部通知。

回滚时使用 `systemctl --user disable --now quant-yahoo-daily.timer` 停止后续执行，并确认 oneshot service 是否仍在运行；必要时停止该 service。保留已取得的批次、状态与审计记录，不删除现有行情或固定研究快照。
