## 规则和分类口径

| 检查 | 口径 | 结果/可追溯性 |
| --- | --- | --- |
| 重复日期 | 复用已完成的全文件结构审计；其策略为稳定输入顺序下保留最后一条 | 本次审计中无 `duplicate_date_keep_last` 记录。已清理的重复日期不能由 structural-v1 反推，故未伪造日期。 |
| OHLC/缺失/负值 | 结构审计标记的文件逐行从派生层展开 | `ohlc_relation_invalid` 211 行；`missing_required_value` 418,615 个字段值。每行含 ticker、稳定 key、日期、provider/namespace、行情 source、原路径和字段名。负价/负量在本次结构审计中为零。 |
| 交易日 | 不从「某日无 bar」推断停牌 | 周末/节假日、停牌与供应商漏数必须有权威交易日历和证券状态才能区分。报告不把任何缺失行标为停牌；下载 manifest 的最新失败另列为 `supplier_download_gap`。 |
| ticker 复用 | 合并证券主表按 ticker 多生命周期记录 | `ticker_lifecycle_reuse_candidate` 1,322 条，带 IPO/退市日期和主表来源；只是候选，P1-03 才做身份判定。 |
| 来源冲突 | 同 ticker 跨 provider/namespace 文件不拼接 | `source_conflict_unmerged` 626 条，带该文件最早日期和 `source`；保持未合并。 |
| 供应商覆盖缺口 | 三份 manifest 按 provider+输出路径取最新状态 | `supplier_download_gap` 9,517 条，含请求区间、完成时间、来源、重试次数和错误类型；不等同于交易所停牌或退市最终结果。 |

`missing_provenance_metadata` 6,931 条仍保留在上游结构审计摘要；它是文件级元数据完整性问题，不伪装为一个精确的行情日期问题。

```bash
PYTHONPATH=src /home/davidou/quant/venv/bin/python -m quant_data.cli quality-report \
  --audit-root /home/davidou/quant/data/audit/structural-v1 \
  --derived-root /home/davidou/quant/data/derived/structural-v1 \
  --security-master /home/davidou/quant/data/metadata/security_master.consolidated.parquet \
  --report-output /home/davidou/quant/data/audit/quality-v1 \
  --manifest /home/davidou/quant/data/manifests/download.jsonl \
  --manifest /home/davidou/quant/data/manifests/alpaca-retry/download.jsonl \
  --manifest /home/davidou/quant/data/manifests/alpaca-delisted/download.jsonl
```

这条命令只读输入，允许覆盖同一独立报告快照以重建当前规则版本；不应把 `--report-output` 指向 raw 或 derived。
