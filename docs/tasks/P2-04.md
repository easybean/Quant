# P2-04 候选运行器最小验证与决策

执行日期：2026-09-08。

## 结论

本轮**不采用任何候选运行器作为可交易/可回测适配器**。NautilusTrader 和 VeighNa 仅保留为候选；能力登记继续全部为 `unverified`，所有产品请求仍被阻断。

这是一个完成的否决性决策，而不是安装失败后的默认放行。P3 开始前，需新增一个按目标产品、订单、部分成交和账务黄金样例的适配器验收任务；不应以本记录中的框架导入或数据对象构造作为兼容性证据。

## 隔离环境与实际证据

- 新建本地隔离环境：`.venv-p2-04`，Python `3.11.6`；未读取项目行情、未连接账户、券商、交易所或 CTP 网关。
- NautilusTrader `1.221.0`：实际创建 `BacktestEngine`、现金账户、测试权益工具，写入一条合成 1 分钟 OHLCV Bar 并 `run()` 后 `dispose()` 正常退出。该证据只覆盖“本机离线引擎可处理一条美股分钟 Bar”。
- VeighNa 核心 `4.4.0`：离线构造 `rb2501.SHFE` 的 1 分钟 `BarData`，并构造 `Offset.CLOSETODAY`、`OrderType.LIMIT` 的 `OrderRequest`。这只证明国内期货的开平/平今枚举可表达。
- `vnpy_ctp 6.7.11.4`：macOS ARM 本机构建失败，原因是随包 CTP 头文件缺少其绑定代码引用的字段；适配器没有安装，也没有尝试连接网关。因此 CTP 生命周期、回报、结算和国内规则执行均为 `unverified`。

安装/验证命令（均在隔离环境）：

```bash
python3 -m venv .venv-p2-04
.venv-p2-04/bin/pip install nautilus_trader==1.221.0
.venv-p2-04/bin/pip install --no-deps vnpy==4.4.0
```

Nautilus 合成运行使用 `BacktestEngine.add_venue`、`add_instrument`、`add_data`、`run`、`dispose`；VeighNa 仅导入 `vnpy.trader.object` 与 `vnpy.trader.constant`。所有输入均在命令内构造，未下载或写入行情。

## 采用决定与迁移成本

- **当前决定：不采用、不接入 P3。** 保留项目自己的 `InstrumentDefinition`、时间模型、能力门禁和 Decimal 黄金账本作为稳定边界。
- **Nautilus 的潜在迁移成本：** 将 stable instrument ID、日历/available-time、原始成交价和账本映射到其模型；为每种订单和费用/公司行动写适配器与黄金回归。当前最小 Bar 路径不覆盖这些工作。
- **VeighNa/CTP 的潜在迁移成本：** 先在目标 Linux 服务器上取得可编译、与实际 CTP API 版本匹配的适配器；再处理开平/平今、合约规则有效期、夜盘、结算和断线/回报重放。macOS 构建失败不外推到服务器，也不构成其可用证据。
