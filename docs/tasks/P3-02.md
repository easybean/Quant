# P3-02 策略定义与首批模板

执行日期：2026-09-09。

## 交付

- 新增 `quant_data.strategies`，只定义不可变的策略意图、数据契约、目标权重和可复现记录；没有账户、券商、行情文件、回测运行器或下单调用。
- 固定策略 schema 为 `p3-02-v1`，并固定两个模板版本：`buy-and-hold-v1`、`dual-moving-average-v1`。调用方不能用任意版本字符串替代。
- 买入持有模板要求一个研究代码和 `start_date`，起始日之前输出全现金，之后输出配置的单标的目标权重及余下现金权重。
- 双均线模板要求一个研究代码、`fast_window` 和更大的 `slow_window`。它对调用方提供的、已经可见的日线收盘价计算简单均线；快线严格高于慢线时输出目标多头，否则输出全现金。可用历史少于慢线窗口时也输出全现金，并说明原因。
- 参数 schema 是可显示的普通字典；校验返回字段级、可读问题。窗口、日期、代码空白、未知参数、`NaN`/无穷、零或超出范围的权重均失败关闭。
- `DataRequirements` 强制保存固定数据/资产池/日历版本、日线频率、收盘字段、声明的价格口径和 `available_time`。不允许 `latest`、`current`、未知价格口径或用事件时间替代可用时间。
- `ObservedClose` 绑定 P2-02 `MarketEvent`。计算目标前逐条调用其 `require_available_at`，并拒绝未来交易日、重复交易日和其他代码的观测，因此模板接口不能直接读取未来信息。
- `ReproducibilityRecord` 包含 schema、模板和参数、数据契约、代码版本和 UTC 创建时间，可稳定 JSON 序列化；它不包含收益或“已运行”声明。

## 运行器能力门禁

策略定义与参数校验不依赖运行器。P3-03 的受限路径只要求精确的 `bar_frequency:1d`、`order_type:limit`；市场单或再平衡语义需要独立验收，不能由模板隐式要求。

P2-05 的合成日线限价路径已在目标 Linux 锁定版本黄金验收；这只代表 P3-03 可在更严格的合成数据/资产池门禁下调用该受限路径，不代表真实行情回测、市场单或完整策略运行已验收。此模块本身不读取行情或账户。

## 边界与后续

- 本项未读取、下载、移动或改写 raw/derived/curated 数据；数据要求中的版本是调用方以后传入的已验收快照标识，并不宣称当前可用资产池已经可用于回测。
- 未改 API、UI、后台任务、运行器、账务或部署；也没有连接任何外部账户。
- P3-03 仍依赖 P3-01 和真正通过的运行器/成本模型验收。只有届时的运行器能通过能力门禁，策略定义才可能被外层任务系统提交。
