# P2-02 日历和事件时间模型

执行日期：2026-09-08。

## 交付

- 新增 `quant_data.time_model`。`MarketEvent` 强制 `event_time`、`available_time`、`ingest_time` 为 UTC 感知时间；事件带市场 IANA 时区、交易日、来源、schema/revision。策略仅能用 `available_time <= strategy_time` 的事件；提前读取会抛出 `PermissionError`，防止后来可见的数据进入过去的回测时点。
- 新增有界 `VenueCalendar`、`SessionSegment`、`CalendarOverride` 和 `CalendarDecision`。夜盘段可通过 `trading_day_offset` 挂到下一交易日，IANA 时区自动处理 DST。
- 日历不内置或伪造完整交易所假日表。未声明 `weekly_schedule_verified=True` 的周规则一律返回 `unknown`；覆盖区间外返回 `unknown`；已知但不可用的时段可返回 `blocked`。调用方需保存带来源和有效覆盖范围的日历快照，才可标示 `open`/`closed`。
- 新增 `effective_rule_at(instrument, on_date)`：按传入历史日期返回唯一生效规则，不会回退到“最新规则”；规则缺失返回 `None`，规则重叠时失败关闭。

测试覆盖：

- 美股 2024-01-05 16:00 EST 收盘（21:00 UTC）与五分钟后数据可用；发布前读事件被阻断。
- 国内期货周日 21:00 上海夜盘及跨午夜段，均归属下一周一交易日。
- 美国 2024 年 DST 前后的 09:30 开市从 14:30 UTC 变为 13:30 UTC。
- 加密货币 UTC 交易日的 24x7 明确周规则。
- 覆盖区间外 `unknown`、未验证边界 `blocked`、仅有周时段而无可验证日历时 `unknown`。
- 同一合约在不同历史日期的规则版本查询，以及无规则日期和错误 datetime 输入。

## 边界与后续

- 这不是完整交易所假日历，也不推断单证券停牌、提前收市或交易所临时公告；这些要以带日期、来源和版本的覆盖数据补入 `CalendarOverride` 或新的日历快照后才能放行。
- 本项没有读取、下载、移动或改写行情数据，没有连接账户，也没有部署。
- P2-03 应基于本模型的 `trading_day`、`available_time` 和 `effective_rule_at` 写入可人工核算的订单与账务黄金样例。
