# P2-01 M0 合约模型与运行器能力审查

执行日期：2026-09-08。

## 交付

- `InstrumentDefinition` 新增不可变 `identity_key` 与 `symbol_history`。`instrument_id` 必须是 `venue:identity_key`；交易代码只是带生效区间的映射。`validate_instrument_set` 会阻止同一 venue、相同时段的 ticker 被两个生命周期复用，同时允许改名和不重叠的历史复用。
- `InstrumentRule` 现要求 `valid_from`、`rule_version`、数量单位和有限正数的 tick/lot；规则区间不能重叠。合约乘数、最小名义金额也拒绝 `NaN`、无穷、零和负数。
- 校验资产类别与产品的唯一组合；加密现货必须有 base/quote/settlement，永续/交割合约还必须声明 linear 或 inverse，期货/交割必须有到期日。
- 能力登记改为精确键，例如 `bar_frequency:1d`、`order_type:limit`、`funding:perpetual`、`open_close:close_today`。泛化布尔需求（如 `order_type=True`）返回可展示的 `unknown` 问题，而不会被当成支持。
- Backtrader、Nautilus、VeighNa 的每一个市场产品组合均保留 `unverified`；登记文案明确框架/包存在不是业务规则证据。P2-04 取得逐产品黄金样例前，任何运行请求都会阻断。

## 验证

```bash
PYTHONPATH=src .venv/bin/python -m pytest -q tests/test_instruments.py tests/test_market_capabilities.py
PYTHONPATH=src .venv/bin/python -m py_compile src/quant_data/instruments.py src/quant_data/market_capabilities.py
```

结果：`10 passed`；编译通过。

测试覆盖：证券改名、ticker 非重叠复用与重叠拒绝、身份不应取 ticker、资产/产品组合、加密结算字段、期货到期字段、规则有效期重叠、`NaN`/正负无穷/零的数值边界，以及精确能力要求、泛化要求和未验证运行器阻断。

## 边界与后续

- 本项只建立模型和校验，不把 P1 主表中基于 ticker 的现有文件反向绑定成稳定身份；P2-02 将把事件时间、日历和生效日查询接入。
- 没有连接券商、交易所或账户，也没有下载、移动、读取或写入行情数据。
- 没有部署：当前 API/UI 尚未开放合约或运行器接口。后续 P2-03 先定义账务黄金样例，P2-04 才能更新任何具体能力为已验证。
