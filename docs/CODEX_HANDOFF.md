## 5. 已确定的重要架构决策

### 5.1 产品范围

目标不是单一美股回测脚本，而是可扩展的多市场量化平台：

```text
数据 → 研究 → 因子 → 策略 → 组合 → 风控 → 执行 → 交易 → 监控/归因
```

目标市场：

- 美股；
- 国内期货；
- 海外期货；
- 加密货币现货；
- 加密永续；
- 加密交割合约。

当前阶段只做研究、回测和模拟交易，不连接真实资金交易。

### 5.2 标的身份和数据时间

- ticker/symbol 不是稳定主键；统一使用稳定的 `instrument_id`。
- 证券身份、代码、交易所、币种、合约规则和有效期必须版本化。
- 数据至少区分 `event_time`、`available_time`、`ingest_time`。
- 内部统一 UTC，展示层再转换时区。
- 必须以 `available_time` 防止未来函数。

### 5.3 数据分层

```text
Raw（不可变）
  → Normalized
  → Curated / Research Snapshot
  → Features / Factors
  → Artifacts / Reports
```

- raw 永不被清洗结果覆盖；
- 修复、复权、特征和因子均产生新版本；
- provider 数据必须隔离，不能静默混并；
- 研究与回测只消费明确版本的数据快照。

### 5.4 策略、组合、风控分层

- 因子是基本研究信号，不等于完整策略。
- 策略把因子/指标转为目标仓位，并含入场、退出、调仓和局部约束。
- 组合层负责多策略资金分配、相关性、集中度和风险预算。
- 风控层独立于策略，负责账户级、组合级和平台级硬限制。
- Kill Switch 必须在策略无法绕过的位置执行。

### 5.5 统一订单状态链

目标链路：

```text
TargetPosition
  → OrderIntent
  → RiskDecision
  → ExecutionPlan
  → Order
  → Fill
  → LedgerEntry
```

关键原则：

- 每个账户只有一个订单写入者；
- 下单/回报处理必须幂等；
- 订单、成交和账本需要可恢复、可审计；
- 回测和实盘尽量共享策略规格与事件语义，但不承诺不同框架之间直接复用同一段执行代码。

### 5.6 技术栈角色

- React + TypeScript：主管理端；
- FastAPI + Python：服务 API；
- Parquet：当前行情/研究数据；
- SQLite：当前草稿、任务、实验和账本状态；
- PostgreSQL/DuckDB：架构目标或后续候选，当前没有实际接入；
- Qlib：研究和机器学习能力候选，不作为交易内核；
- NautilusTrader：多市场事件驱动回测/模拟运行内核候选，目前只完成窄范围验证；
- VeighNa/CTP：国内期货接入候选；
- LEAN：保留为可替代引擎候选，当前未安装/集成。

### 5.7 Python 环境

- 不升级或替换 Linux 系统 Python 来迁就单个量化框架；
- 不同框架使用独立虚拟环境/runtime；
- 数据、API、Nautilus 可使用不同 Python 版本，通过稳定文件/API/任务协议连接。

### 5.8 安全边界

- 原始行情和已有用户数据必须保留；
- 密钥值不进入页面、仓库或日志，只保存安全引用名；
- 当前不开放任意代码执行；
- 外部 paper/实盘接入前必须先有可执行风控、幂等订单和故障恢复。
