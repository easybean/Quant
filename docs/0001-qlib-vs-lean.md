# Qlib 与 LEAN 选型记录

状态：待 PoC 验证（2026-08-28）

## 它们分别解决什么问题

### Microsoft Qlib

Qlib 是面向 AI 的量化研究平台，强项是数据表达与特征、因子研究、机器学习训练、实验管理、组合构建和回测分析。它适合回答“用哪些数据训练什么模型、如何产生和评估信号”。

Qlib 有在线模型更新与推理相关模块，但它不是开箱即用的行情网关、券商柜台、账户中心或完整模拟交易运营平台。真实实时行情采集、可靠消息传输、逐笔撮合、账户恢复、风控、权限和监控仍需补齐。官方 README 目前还提示官方数据集暂时不可用，因此生产数据必须自行采购、清洗并持续维护。

### QuantConnect LEAN

LEAN 是模块化、事件驱动的算法交易引擎，覆盖研究、历史回测、订单/持仓、费用/滑点/成交模型以及实盘或模拟盘运行。它适合回答“行情到来后怎样驱动策略、怎样管理订单与组合、怎样复用回测和实时执行逻辑”。策略可用 Python 或 C#，引擎主体为 .NET/C#。

LEAN 能在本地运行并支持 Paper Trading，但官方 LEAN CLI 的本地部署流程依赖 Docker、QuantConnect 登录，当前官方文档还要求付费组织层级。直接基于开源引擎构建可以降低对 CLI 工作流的依赖，但团队需要自行承担编译、配置、升级、插件与运维成本。

## 对本项目的适配度

| 能力 | Qlib | LEAN | 本项目仍需建设 |
|---|---|---|---|
| 因子/ML 研究 | 强 | 可做研究，但不是核心优势 | 数据治理、实验规范 |
| 历史回测 | 强于截面预测和组合研究 | 强于事件驱动与订单级仿真 | 统一规则与结果核对 |
| 实时行情驱动 | 需较多集成 | 原生架构更合适 | 行情供应商适配与许可 |
| 模拟订单/账户 | 非核心 | 内置 Paper Brokerage 与模型 | 市场规则、持久化、审计 |
| 内网私有部署 | 可以 | 引擎可以；CLI 有账号/付费约束 | 镜像仓库、离线依赖、监控 |
| A 股开箱能力 | 研究案例较友好 | 官方券商清单无主流中国券商 | 行情、证券主数据及交易规则适配 |
| Web 管理平台 | 无 | 开源引擎本身不等于完整 Web 平台 | 前后端、权限、任务和报表 |

## 能否满足“真实数据做模拟盘”

**能作为核心组件，但任一项目单独使用都不能完整满足。**

- 若重点是日频/分钟级选股、因子与机器学习：Qlib 很合适，输出标准化目标仓位或交易信号给执行层。
- 若重点是行情事件驱动、订单生命周期、多资产和回测/模拟盘逻辑复用：LEAN 更接近所需执行内核。
- 若只做低频 A 股模拟盘，完整引入 LEAN 可能偏重；在 PoC 中应与一个较薄的 Python 模拟执行服务比较维护成本。
- 若做美股、期货、外汇或加密资产，且官方已有对应数据源/券商模型，LEAN 的收益更明显。

推荐的候选组合是 **Qlib（研究）+ 独立信号契约 + LEAN（回测/模拟执行）**，但必须通过目标市场 PoC 后再定案，不建议让 Qlib 直接承担订单和账户系统。

## A 股场景必须验证

- 交易日历、集合竞价、午间休市、停牌和退市；
- 股票 T+1、买入整手/卖出零股、涨跌停与不同板块限制；
- 佣金、印花税、过户费、最低佣金和滑点；
- 前/后复权口径、除权除息、代码/上市状态变化与幸存者偏差；
- 涨跌停或无成交量时的不可成交逻辑，不能用“看到价格即全部成交”；
- 行情断流、乱序、重复、迟到，以及进程重启后的账户恢复和幂等性。

## PoC 验收门槛

1. 至少 20 个连续交易日真实行情驱动，无重复订单或账实不一致。
2. 同一策略在历史回放与实时模拟中的决策可解释，差异有可追踪原因。
3. 手续费、交易限制和撮合结果通过独立样例校验。
4. 断网、行情断流和进程重启后可恢复，且不会重复成交。
5. 每个行情事件、信号、风控决定、订单和成交均可审计。

## 许可证与商业使用

Qlib 使用 MIT License；LEAN 使用 Apache License 2.0。两者通常都允许企业内部使用和修改，但仍应由公司法务确认依赖项、行情数据合同、再分发和商标要求。开源许可不等于免费获得实时或历史行情授权。
