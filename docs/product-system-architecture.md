# 多市场量化工作台：产品与系统架构 V1

状态：设计提案，不代表已经实现。本文不授权实盘交易，也不修改现有部署。

## 1. 产品定位与边界

面向个人的、内网部署的、多市场量化研究与模拟交易工作台。让不会写代码的使用者可以通过界面浏览行情和因子、组合策略、运行回测、比较结果、启动和管理模拟策略；同时为自定义 Python 策略保留扩展接口。

核心目标不是一次堆齐所有开源项目，而是形成可复现、可解释、账实一致的闭环：选数据 → 提出假设 → 构建策略 → 回测验证 → 模拟运行 → 分析改进。

### 1.1 市场范围

| 市场 | 产品范围 | 必须独立建模的规则 |
|---|---|---|
| 美股 | 普通股票、ETF、指数参考数据 | 公司行为、退市、交易时段、可用资金、借券及费用；指数本身不当作可下单证券 |
| 国内期货 | 商品期货、金融期货 | 合约乘数、夜盘与交易日、开平和平今、保证金、涨跌停、到期与交割约束 |
| 海外期货 | 股指、利率、能源、金属、农产品等上市期货 | 各交易所日历、币种、乘数、结算、到期、首次通知日和换月 |
| 虚拟货币现货 | 不同交易所的交易对 | 基础币/报价币、交易精度、最小名义额、手续费币种、全天交易 |
| 虚拟货币永续 | 稳定币本位、币本位；线性/反向 | 标记价、指数价、资金费、逐仓/全仓、维持保证金及清算规则 |
| 虚拟货币交割合约 | 有到期日的期货合约 | 到期结算、交割费用、合约乘数、线性/反向计价、换月 |

“合约”在本版按永续和有到期日的交割期货理解；期权暂不纳入验收范围，数据模型预留扩展。现货杠杆借贷也不是普通现货的默认能力。国内/海外指市场覆盖，不意味着任何账户均可接入所有交易场所。

### 1.2 默认约束

- 开源、免费数据优先；数据缺口必须显式展示，不承诺免费获得全市场十年完整历史。
- 原始数据保留且不可就地清洗覆盖；衍生数据和实验均版本化。
- 首先支持日线和分钟级研究，不以高频、L2/L3撮合精度为第一版目标。
- 回测、历史回放、本地实时模拟、外部模拟账户相互隔离。实盘入口默认不实现、不显示。
- 一套产品界面和策略定义，不强求所有资产使用同一套成交、保证金和结算公式。
- 首版单机、模块化单体；行情接入、交易运行和批量计算独立进程，避免互相拖垮。

### 2.1 全局交互规范

- 左侧一级导航；页面内用页签/列表切换子功能；顶部显示当前运行环境、连接状态、通知和全局搜索。
- 市场筛选只影响浏览，不暗中修改策略配置。策略和账户的环境固定在运行实例中，不能靠切换顶部下拉框迁移。
- 采用文字列表、选中底色/边线、卡片和按钮组表达选择；不使用单选框/复选框充当导航。危险操作用明确动作名称和确认说明。
- 颜色不单独承载含义：状态同时有文字/图标；涨跌色可配置，风险红色与行情涨跌色语义分开。
- 空状态区分：尚未配置、没有数据、加载失败、权限不足、规则不支持。不能全部显示为空表。
- 所有金额显示币种；数量显示股/张/基础币；时间显示时区和期货交易日。汇总资产按报告币种折算，但不表示跨账户保证金可以共享。
- 普通使用路径不依赖终端。首次操作有向导，复杂参数默认折叠；Notebook 和代码编辑属于高级功能。

### 2.2 因子百科的固定布局

保留用户确定的两列主结构：左列所有主分类，右列该分类全部因子，默认不分页隐藏少量条目，数量大时搜索和虚拟列表。点击因子在右侧详情抽屉中查看定义，不另加一套分类树。

右列项目展示：中文名、代码、简短用途、适用市场、可计算状态。详情展示公式、参数、输入数据、信号解读、滞后性、局限、来源和公式版本，以及“送入因子研究”。来源不是并列分类导航。

现有技术因子的九类可以继续作为当前目录；后续引入价值、质量、期限结构、资金费等经济类因子时，再按覆盖范围扩充主分类。不得仅根据名称把股票估值因子用于期货，或把同名指标视为公式相同。Alpha360仍隐藏，定义保留；Alpha158的本地实现须标注兼容程度，不能默认等同官方实现。

### 2.3 三个关键操作流程

**新建回测**：选择策略版本 → 选择市场/资产池/数据快照 → 设置日期与频率 → 配置资金、成交和费用 → 设置风险与基准 → 查看缺失数据和能力检查 → 提交 → 报告。

阻断项必须先解决，例如缺少结算价、规则不支持、策略需要做空但账户不支持；一般警告可以在明确记录接受后继续。接受警告不等于结果可信。

**启动模拟**：从已验证策略版本创建实例 → 选择本地模拟或外部模拟账户 → 固定参数与限额 → 校验行情和规则 → 预热 → 同步账户与订单 → 启动。状态为草稿/检查中/预热中/运行中/暂停发单/故障待核对/已停止。停止按钮要区分“停策略”“撤挂单”“平仓”，不能混成一个动作。

**比较研究结果**：选择实验 → 自动展示不同数据、公式、参数和成本版本 → 按同区间比较 → 查看样本外表现和失败记录 → 写结论 → 保存候选策略。不能只保留最优参数结果。

## 3. 逻辑架构与模块边界

这不是九个串行页面。风险、账务、审计和监控贯穿所有运行环境；因子是策略可选输入。

```text
                  Web 工作台 / 高级研究接口
                            │
                 应用 API / 身份与权限 / 任务调度
                            │
       ┌────────────────────┼─────────────────────┐
       │                    │                     │
  数据与规则服务       研究/因子/策略注册库      账户/组合/风控配置
       │                    │                     │
       └────────────────────┼─────────────────────┘
                            ▼
             策略运行器：事件 → 信号 → 目标仓位
                            │
               组合分配 → 风险检查 → 执行计划
                            │
                      订单管理 OMS
                 ┌──────────┼──────────┐
                 ▼          ▼          ▼
           历史成交模拟  实时本地模拟  外部模拟账户网关
                 └──────────┼──────────┘
                            ▼
                  成交/结算 → 账务与持仓
                            │
                   对账 / 风险 / 绩效 / 审计

      旁路：不可变原始数据、事件日志、版本快照、监控和备份
```

### 3.1 模块合同

| 模块 | 拥有的数据/职责 | 不负责 |
|---|---|---|
| Instrument & Rules | 资产身份、合约参数、日历、有效期规则 | 生成投资信号 |
| Data | 采集、原始保留、清洗派生、质量报告、时间点查询 | 在缺失处伪造有效行情 |
| Research & Factor | 特征计算、检验、实验和公式版本 | 因“有指标”就声明策略有效 |
| Strategy | 消费可见数据，产生信号或目标持仓 | 直接绕过风控调用券商 |
| Portfolio | 多策略资金分配、目标合并、策略归属 | 把隔离账户抵押品混用 |
| Risk | 持续及发单前检查、限额与处置 | 无可靠状态时盲目强平 |
| Execution | 目标差额转订单、分批执行、取消重报策略 | 擅自扩大组合风险预算 |
| OMS & Gateway | 订单状态、幂等、外部连接、恢复同步 | 研究公式和绩效解释 |
| Ledger & Reconciliation | 可审计资金事件、费用、结算、持仓核对 | 用图表累计数替代账本 |
| Analytics & Operations | 指标、告警、归因、资源、审计与备份 | 在浏览器中决定实际订单 |

只设一处账户订单写入权。底层框架已有OMS/风控/持仓模块时，通过适配层使用，不再另造一个同时控制同账户的竞争OMS。平台账务保存可追溯日志和读模型；运行时持仓缓存、平台账本及外部账户必须可核对。

## 4. 技术选型与开源项目位置

以下是设计选型，不是已经安装或保证全覆盖的支持声明。

| 层 | 方案 | 原因及边界 |
|---|---|---|
| 产品前端 | React + TypeScript | 建立统一工作台、表格、详情抽屉、图表和运行状态；旧Streamlit暂时保留 |
| 应用服务 | FastAPI；Python领域模块 | 与现有Python研究代码衔接，前端不耦合计算实现 |
| 元数据/账务 | PostgreSQL | 保存用户配置、实验索引、订单事件、账务、任务、审计 |
| 行情/特征文件 | Parquet + 文件清单；DuckDB查询 | 复用现有文件，适合单机研究；查询层不直接修改原始文件 |
| 后台任务 | 首版数据库任务队列 + 独立Worker | 租约、心跳、超时和幂等；后续有证据再引入Redis/专用消息中间件 |
| 研究计算 | 现有ta和因子实现；Qlib作为可选研究组件 | 校准公式后复用，不把Qlib当完整交易系统 |
| 现有回测 | Backtrader保留为历史研究运行器 | 旧报告仍可追溯；不强行承担全部多市场账务 |
| 多市场运行内核 | NautilusTrader作为首选验证候选 | 先做最小兼容验证，再锁定版本和产品支持范围 |
| 国内期货连接 | VeighNa/CTP作为接入候选 | 独立网关或原生运行器，必须验证开平仓等协议语义 |
| 运行与维护 | 独立进程、固定依赖、服务管理、统一日志 | 先在单机可靠运行，不先上Kubernetes或大量微服务 |

Nautilus官方架构提供共享内核及回测、sandbox、live等环境区分，但这些框架枚举不能直接等同产品的“真实资金”权限；具体网关、产品和规则仍需验证。[官方架构](https://nautilustrader.io/docs/latest/concepts/architecture/)

VeighNa有官方CTP接口项目，这证明有接入基础，不代表当前服务器已有可用期货模拟账户，也不保证全部协议字段可无损桥接到另一引擎。[官方CTP接口](https://github.com/vnpy/vnpy_ctp)

### 4.1 引擎选择的验收闸门

不同时铺开LEAN、Nautilus、VeighNa三套完整平台。先以统一协议验证首选内核，国内期货验证CTP桥接。若桥接不能正确表达开平、平今、持仓模式或恢复语义，国内期货采用隔离的VeighNa原生运行器，明确显示能力差异；不为追求“同一个引擎”牺牲正确性。

共用的是StrategySpec、数据快照、风险配置和报告标准。Python策略能否原样跨引擎取决于其依赖的接口，必须标注，不承诺所有第三方策略直接通用。LEAN保留为评估替代，不在首期叠加部署。

每个运行器暴露能力清单：市场/产品、频率、订单类型、开平方式、持仓模式、保证金、线性/反向、资金费、到期结算、恢复与对账。任务启动前匹配能力；不支持则阻断，不静默降级。

## 5. 统一数据模型

### 5.1 资产与规则

稳定的instrument_id，不直接使用ticker作为唯一身份。核心字段：asset_class、venue、venue_symbol、base/quote/settlement_currency、product_type、expiry、multiplier、quantity_unit、tick_size、lot_size、min_notional、calendar_id、timezone、listing/delisting、last_trade/first_notice、rule_version。

保证金模式、费率、价格限制和交易规则使用带生效时间的记录，不能拿今天的参数套十年前。不同交易所的BTC交易对、同一品种不同到期合约是不同资产；连续合约是研究序列，不是可下单资产。

### 5.2 数据与时间

MarketEvent至少记录event_time、available_time、ingest_time、source、sequence（有则保留）、instrument_id、schema_version和数据修订版本。内部时间UTC，展示按市场时区；期货另存交易日。策略只能读取当时可获得的数据，而非后来补全的最终版本。

数据分层：

```text
raw/          原始供应商内容与采集元信息，只追加、保留修订
normalized/   标准字段、单位和时间，不隐藏来源
curated/      质量规则、复权/映射结果及异常报告
features/     特征/因子输出，绑定公式、参数和输入快照
artifacts/    回测报告、模型、日志、实验结论
```

逻辑目录不要求立即移动现有raw文件。用manifest登记其位置、校验和、时间范围和版本，迁移用新目录发布。股票的正价格规则不能机械套到可能出现负价格的期货数据。缺失数据区分休市、停牌、未上市、供应商缺口，不能一律前向填充成交量或可交易价格。

### 5.3 研究与运行对象

- DatasetSnapshot：资产池历史成员、数据清单、质量版本、复权与换月规则。
- FactorDefinition/Version：定义、输入、窗口、可用时点、市场适用性、实现版本、校准状态。
- StrategySpec/Version：信号、目标仓位规则、参数、依赖、能力要求。
- Experiment/Run：数据、代码提交或内容哈希、依赖锁文件、随机种子、参数、成交/费用模型、结果与告警。
- ModelArtifact：训练区间、特征版本、标签定义、验证方法及上线批准记录；机器学习为后续可选模块。
- Account/Portfolio/Sleeve：真实或模拟账户、组合、虚拟策略资金归属。Sleeve不是交易所独立账户。

### 5.4 订单与账务对象

TargetPosition → OrderIntent → RiskDecision → ExecutionPlan → Order → Fill → LedgerEntry。

所有对象关联run_id、strategy_version、account_id；订单包含client_order_id、外部ID、开平标志、reduce_only、持仓模式、时间有效性及数量单位。金额和数量在订单/账务边界使用十进制定点语义，研究数组可使用浮点。

Order不是简单单向链条：撤单处理中仍可能成交；取消的订单可以已有部分成交；提交超时可能是状态未知而非失败。必须分别记录请求、确认、累计成交和剩余数量。

账务至少分解现金、冻结、保证金、已实现/未实现盈亏、费用、资金费、分红、结算和虚拟出入金。期货逐日结算后不可再次把同一盈亏计入收益。币本位和线性合约用不同估值模型；稳定币不硬编码为永远等于美元。报告汇率必须带时间和来源。

## 6. 各市场正确性要求

| 主题 | 设计要求 |
|---|---|
| 美股公司行为 | 保存原始价和公司行为；研究复权与执行原始价口径明确，股数/现金正确调整 |
| 退市 | 历史成员及退市标识可追溯；最终收益/兑付缺失必须警告或阻断，不自动按零或最后价假装完成 |
| 股票做空 | 借券可得性和借券成本缺失时，不给出无约束做空的可信声明 |
| 期货连续序列 | 定义换月时点、可用信息及调整方法；信号可来自连续序列，成交必须落到真实到期合约 |
| 期货换月 | 平旧开新两笔成交、费用、价差和保证金影响入账；不靠替换symbol让持仓无成本跳转 |
| 国内期货 | 开平/平今、昨今持仓、夜盘交易日、涨跌停、结算和合约规则逐品种验证 |
| 海外期货 | 本地日历、夏令时、币种、首次通知/最后交易日及自动避交割策略 |
| 永续资金费 | 使用实际结算时点和规则，不假定所有市场固定每8小时；预测费率与已结算费率分开 |
| 合约风险价格 | last、mark、index分开；成交价与保证金/清算用价不能混用 |
| 保证金与清算 | 全仓/逐仓、风险档位、线性/反向分别实现；近似模型明确标注误差与不支持情况 |
| 日线/分钟成交 | 不能从OHLC推断唯一盘中路径；同bar触发止盈止损使用公开的保守规则或细粒度数据 |
| 多策略 | 同账户合并目标后保留策略归属，不能把相互抵消的虚拟订单都算作真实成交 |

QuantConnect官方期货文档也将连续合约映射变化与实际合约交易分别处理，可作为实现检查参考，不意味着本项目必须使用LEAN。[期货数据与换月](https://www.quantconnect.com/docs/v2/writing-algorithms/securities/asset-classes/futures/handling-data)

## 7. 研究、回测与模拟的质量标准

因子百科是知识目录；因子研究才产生统计证据。可计算、公式已校准、数据充足、样本外有效是不同状态，不合并成一个“可用”标记。

横截面股票因子可进行IC/RankIC和分组测试；单资产时序信号应采用相应的预测、交易和样本外评价。去极值、中性化、标准化不是所有因子通用的必经流程。训练得到的变换参数不得从测试集拟合。

回测报告强制列出：数据范围及覆盖缺口、资产池口径、复权/换月方法、成交模型、费用、滑点、杠杆/保证金、基准、时间粒度、代码和规则版本。交易成本拆项，不能用一个统一滑点率掩盖全部差异。

验证包含样本外、滚动验证、参数敏感性和成本压力测试；标签窗口重叠时处理训练验证泄漏。保留失败实验与搜索规模，避免只展示最优Sharpe。基准必须匹配市场与风险，不把所有策略都对比标普500。

本地模拟使用实时行情和本地撮合；外部模拟使用供应商模拟账户。两者都不是实盘成交保证；测试环境流动性、资金费和规则可能不完全等同真实市场，报告必须标明来源与限制。

## 8. 风控、可靠性与安全

### 8.1 风控

规则分为账户、组合、策略和资产层。包括订单数量/名义额、净/总敞口、杠杆、集中度、保证金缓冲、回撤、频率、价格偏离、行情陈旧、到期禁入和连接异常。具体阈值由用户配置，不把示例值当投资建议。

组合检查不能替代发单前检查；成交、撤单和结算后再次计算。持续风险监控独立于策略线程。策略故障不能关闭风控。

紧急处置默认：停止新风险订单 → 核对状态 → 尽可能撤销已知挂单 → 告警。是否减仓另设明确策略；行情失真或账户未知时，不自动市价清仓。恢复前校验行情、持仓、挂单、限额和处理记录。

### 8.2 订单可靠性

- 持久化订单意图与outbox后再发送；网络超时先查client_order_id及外部状态，不能盲目重复发单。
- 采用至少一次投递、业务去重；不声称网络与外部交易所之间有天然“恰好一次”。
- 每个账户单一订单写入者，租约和fencing防旧进程继续写入；按账户/连接维护事件顺序，不虚构跨市场全局顺序。
- 断线后冻结相关发单、补齐订单/成交/余额、对账再恢复。差异留审计，不能直接覆盖后假装一致。
- 任务状态含排队/运行/成功/失败/取消；Worker心跳过期转待恢复，重跑按任务类型保证幂等。
- 浏览器只显示状态和提交命令；断开浏览器不应停止已运行策略，刷新也不能重复下单。

### 8.3 权限与运行安全

内网仍需登录和最小权限；管理员、研究操作、只读角色可先简化为单用户角色集合。模拟与未来实盘凭证、数据库配置和进程隔离。凭证只在服务端受限存储，日志脱敏，API不返回secret；未来交易连接默认禁止提现权限。

策略代码仅管理员可上传执行；研究Worker限制文件、网络和资源，不能直接读取交易密钥。生产运行器执行固定版本、校验过的策略，不把内网访问视为任意代码执行授权。

监控包括进程心跳、行情延迟、序列缺口、拒单率、对账差异、任务积压、磁盘水位和备份失败。个人单机不承诺高可用；将恢复演练作为验收项。

## 9. 服务接口和部署

### 9.1 接口边界

REST用于查询和提交命令，WebSocket用于进度和事件展示。示例资源：

```text
/api/v1/instruments         资产、合约及规则
/api/v1/datasets            数据快照、覆盖与质量
/api/v1/factors             定义、版本及适用性
/api/v1/strategies          策略定义与版本
/api/v1/backtests           提交与读取回测
/api/v1/experiments         对比与结论
/api/v1/accounts            账户、持仓与流水
/api/v1/runs                模拟实例与状态命令
/api/v1/orders              订单查询、明确的撤单命令
/api/v1/risk                规则、决定与风险事件
/api/v1/capabilities        已验证的引擎/连接能力
/api/v1/jobs                后台任务
```

写操作鉴权、记录审计并使用幂等键；响应包含资源版本，修改时防止覆盖更新。实时消息有序号和快照版本，客户端发现缺口重新读取快照。任何启动接口均重新检查服务端能力和风险，不信任前端筛选结果。

### 9.2 单机进程布局

```text
内网浏览器 → 反向代理 → Web静态资源 / API
                              │
                 PostgreSQL + 文件数据目录
                              │
       ┌──────────────────────┼──────────────────────┐
       │                      │                      │
  数据采集Worker         批量研究/回测Worker      常驻模拟运行器
                                                   │
                                             市场连接/网关
```

现有服务器作为起点；本文没有重新检查CPU、内存、磁盘和服务现状，不给出未经实测的容量保证。首期限制批量回测并发为1，基准测试后再调整；为实时进程预留资源。基础行情与普通因子研究不依赖GPU，ML训练另排队。

不同运行器使用独立锁定依赖环境，不升级系统Python，也不强行把所有库放进同一个venv。是否容器化由CTP等依赖兼容验证决定，不能为统一容器方式破坏连接稳定性。

旧Streamlit入口在迁移期间保留，新前端完成对应功能和回归验收后逐页替换。新服务仅内网开放，端口及代理配置在部署阶段确认。

数据库定期备份，行情manifest及不可再获取的原始数据重点备份，衍生数据按重建成本分级。备份必须有独立介质或独立故障域；同盘复制不算完整灾备。RPO/RTO在容量检查和恢复演练后确定，不预先承诺。

## 10. 数据接入策略与现实边界

| 数据 | 第一阶段 | 缺口处理 |
|---|---|---|
| 美股日线 | 登记已有原始文件、版本和覆盖范围 | 不把下载数量当全市场完整性；退市/公司行为/最终收益单独核验 |
| 国内期货 | 先选代表性合约和明确来源，验证日线/分钟数据及合约规则 | 数据许可、历史深度和模拟连接资格逐项确认 |
| 海外期货 | 先验证合约主数据与到期序列，再接历史行情 | 无足够免费历史时展示覆盖缺口，不能用连续指数冒充完整可交易历史 |
| 虚拟货币 | 从明确交易所的现货、永续及交割样本开始 | 已下架、资金费、标记价、风险档位历史各自评估，不默认齐全 |

Binance公开数据仓库提供现货以及USD-M、COIN-M期货的数据下载说明，可作为候选历史来源；具体产品、起止时间和所需辅助数据须逐项核查，不能据此承诺十年全品种或完整盘口。[官方公开数据仓库](https://github.com/binance/binance-public-data)

每个数据源登记用途许可、限速、覆盖、时间口径、字段单位和修订行为。每个交易连接确认账户资格及所在地区可用性；没有合法可用连接时使用历史/本地模拟，不绕过访问限制。

## 11. 交付路线和验收

先定完整边界，再按最小闭环交付。不以所有菜单都出现作为完成标准。

| 阶段 | 交付内容 | 通过条件 |
|---|---|---|
| M0 基线与协议验证 | 现有功能/数据清单、资产规则模型、引擎能力样例、账务黄金测试 | 每种目标产品至少一个样本完成下单/成交/结算验证；国内开平和加密反向合约不能遗漏 |
| M1 美股研究闭环 | 新工作台骨架、数据目录、因子百科/研究、策略模板、回测报告 | 不用终端完成一次可复现回测；旧数据和旧入口保留；未校准公式明确标注 |
| M2 多市场历史闭环 | 国内/海外期货、加密现货/永续/交割合约逐类开放 | 每类通过专属测试，按能力清单开放；不要求先下载全市场历史 |
| M3 本地实时模拟 | 行情驱动策略、订单与账本、持续风控、恢复和告警 | 连续运行覆盖市场开闭市或结算/资金费事件，故障注入后无重复订单且可对账 |
| M4 外部模拟连接 | 逐个网关接入、状态同步、拒单和限频处理 | 有可用模拟账户，断线/重启/部分成交/撤单竞态测试通过 |
| M5 增强研究与分析 | ML流水线、高级组合优化、细化归因、执行算法 | 用真实需求和对比实验证明价值；不影响已稳定闭环 |

实盘是独立后续项目：需要新的明确授权、账户与权限检查、运行验收及安全审查，不因完成M4自动解锁。

### 11.1 最小黄金测试集合

- 美股：拆股股数与现金、分红、退市缺失提示、历史资产池、同bar成交假设。
- 国内期货：夜盘交易日、开平/平今、结算、涨跌停无成交、到期换月。
- 海外期货：夏令时、跨币种PnL、首次通知/最后交易约束、真实合约换月成本。
- 虚拟货币：现货费用币种、线性和反向PnL、资金费、逐仓/全仓能力、交割结算、reduce-only。
- 公共：部分成交、撤单竞态、重复事件、提交超时、进程重启、陈旧行情、保证金不足、未来数据泄漏。
- 账务：每种产品使用人工可核算的小样本，期末净值与流水可勾稽；同快照/版本/随机种子的重复回测结果一致。
- 迁移：原始文件校验不变，旧报告能打开，未完成模块不冒充可用；至少一次备份恢复测试。

### 11.2 与当前系统的衔接

已有资产按此前工作记录包括美股日线文件、Parquet派生数据、Streamlit界面、ta/本地Alpha因子目录和Backtrader环境。具体数量和可用状态以M0实查为准，本设计不声称已验收。

先复用数据和因子定义、隔离已知公式/字段问题，再抽出服务接口。不能把“有因子名称”“有策略按钮”算作计算/交易能力。旧实现存在的校准问题进入独立清单，不在架构设计阶段顺手重写。

后续实施遵守AGENTS.md省用量约定：主模型一次明确设计、接口和验收；默认一名Terra按模块实施与自测；主模型集中审查。不同时重写前端、回测、数据和网关，也不反复整库扫描。

## 12. 本版决策摘要

1. 统一产品、数据身份、策略描述和报告，保留市场专属规则与适配器。
2. 十个一级菜单覆盖完整产品；按阶段交付，下载任务不单独占页面。
3. 原始文件不覆盖；每个结果绑定数据、代码、公式、费用和规则版本。
4. 账户账务与恢复对账优先于高级优化器、AI和复杂执行算法。
5. 首选运行内核必须过兼容闸门；不承诺所有第三方策略跨引擎原样运行。
6. 从美股研究闭环扩展到各类合约，再做实时及外部模拟；实盘保持关闭。
7. 下一项实施应是M0基线与规则/引擎验证，不是直接重写整个系统。
